# 聚合搜索与账号驱动的来源切换

日期：2026-10-12。状态：设计稿；实现前以库研判和实际平台能力校正。本文对应 [ADR 0007](../adr/0007-current-and-supplementary-sources.md)，交互参考见 [设计演示](search-and-source-switching.html)。演示使用虚构示例结果，不查询平台、不登录账号、不播放音频。

## 本轮目标与范围

目标是两个完整音乐适配器（网易云、QQ 音乐）加一个仅提供播放资源的音源适配器。完整指平台音乐业务接入范围，不表示平台具有所有可选能力。本地聚合歌单后置，原有本地音乐与队列继续保留。音源服务尚未选定，首阶段只接一个明确服务，不提供任意落雪 JS 导入；服务许可、可用性和协议核验后再决定实现。

三个对象应在产品中明确区分：

| 对象       | 示例                       | 决定什么                                   |
| ---------- | -------------------------- | ------------------------------------------ |
| 当前来源   | 网易云音乐                 | 工作区默认的音乐库、发现页与账号体验       |
| 曲目来源   | QQ 音乐                    | 这首歌的稳定身份、详情、平台收藏与写入归属 |
| 资源提供器 | 平台原生／已选择的音源服务 | 从已知曲目解析出播放资源的实现             |

“音源适配器”是提供资源解析能力的适配器；其注册与调用采用独立的资源提供器契约，不虚构一个音乐平台，也不重复注册 `netease` 或 `qqmusic` 来源。界面使用“播放音源”表达用户可配置的资源提供器。仅提供资源的服务不出现在搜索来源筛选中，不能凭空搜索网易云缺少的 QQ 曲目。

## 聚合搜索界面

沿用当前顶部搜索入口、`MusicPage`／`MusicPageHeader`、单曲／歌单／歌手／专辑 tabs、现有虚拟 `TrackList` 与收藏卡片。使用现有黑白语义色、蓝色音乐强调色、标题层级、圆角、间距与紧凑密度；不为每个平台更换主题色或引入独立搜索侧栏。

- 顶部输入改为“搜索音乐”，本地页仍为“搜索本地曲库”。建议词只从当前来源获取，250ms 防抖，不在每次输入时向全部平台发请求；建议不可用仍能直接提交关键词。
- 搜索页标题显示关键词，下方显示“聚合搜索 · 网易云音乐、QQ 音乐”。结果类型 tabs 保持原位置，其下增加来源筛选：`综合`、`网易云音乐`、`QQ 音乐`。综合明确指用户配置且支持该搜索类型的来源，不声称搜索所有已安装服务。
- 搜索来源筛选只改变结果范围，不切换当前来源。当前来源在右上角账号入口持续可见，避免把“查看 QQ 结果”和“切换到 QQ 音乐库”混为一谈。
- 单曲列表增加“来源”列，每行显示完整平台名称；窄窗口把来源文字移至标题下方，不隐藏身份。歌单、歌手、专辑卡片同样显示来源。平台文字不依赖颜色、悬浮提示或图标识别。
- 顶部来源状态行显示“正在搜索／已加载 N 项／暂无结果／请求失败”，失败来源有带图标的重试按钮。N 是本次已加载数量，不是跨来源总数；未知总数不估算。完整页失败和部分失败分别展示。
- 维持统一工作区滚动，滚到底部自动续载，保留已加载结果，失败在末尾按来源重试。页面不提供页码、范围或上一页／下一页；只挂载当前类型面板，长单曲列表使用虚拟渲染。
- 同名跨平台版本保留独立行，按 `{source,kind,id}` 去重；不凭歌名合并。默认排序称“来源推荐顺序”，沿用每个平台原排序，不将不同平台的分数当作同一相关性分数。
- 曲目存在与能否播放分别表达：会员、地区或试听限制不得把已命中的歌曲过滤成“没有找到”。已知限制显示文字说明及可用操作；实际权限尚未取得时不逐行预取音频、不宣称可播放，用户点击时由资源解析确认。

### 结果交付与排序

每次提交固定关键词、类型、当前来源、补充来源顺序与配置修订号，建立查询代次。启用且支持当前类型的来源并发请求首批；先完成的来源立即发布，后来完成的批次追加到末尾，不插入已展示结果上方。一次交付中同时就绪的批次按当前来源、补充来源优先级排序。

这种策略优先首批速度和阅读位置稳定；默认聚合次序不承诺跨平台全局相关性，也不保证当前来源始终占据第一行。界面不增加虚假的全局排名。后续若需要版本分组或统一排序，应另做可解释的匹配模型。

单来源状态分别持有不透明游标、已加载项、结束标记、错误、会话及实例代次。列表末尾一个续载触发器调度仍有后续页的来源，每个来源同一时刻最多一个搜索页请求。失败不推进游标，不自动循环重试；一个来源结束或失败不能终止其他来源的续载。重试失败批次只追加新的稳定引用。

来源筛选复用当前查询已取得的批次和对应游标，只显示所选范围，后续只续载可见来源；未载入的来源按需读取。返回综合恢复既有交付顺序，不丢弃其余来源的结果。类型、关键词、配置或相关账号作用域变化则启动新查询，取消旧请求并拒绝迟到结果。

搜索页状态至少覆盖：初始、首批加载、部分成功、全部成功、部分失败、全部失败、全部为空、续载中、续载失败。未登录、来源停用与平台不支持该类型须分别说明，不将请求失败显示为“暂无结果”。认证不是公开搜索的统一前提，实际账号／曲目可用性由对应适配器判断。

## 账号与来源切换

保留按来源隔离的 `AccountManager`：每个平台可以同时有选中的账号及保存的其他账号。另设宿主当前来源配置；账号选择、当前来源、适配器启用状态是三个独立状态。切换当前来源不会停用另一平台，另一平台的当前账号仍可用于补充搜索与播放。

| 用户动作或系统事件                       | 当前来源行为                                               |
| ---------------------------------------- | ---------------------------------------------------------- |
| 用户发起并完成 QQ 登录                   | 账号和凭据保存成功后，切换到 QQ 音乐                       |
| 用户明确选择保存的网易云账号             | 选中账号成功后，切换到网易云音乐                           |
| 仅在账号页选择“QQ 音乐”查看卡片          | 不切换，卡片上提供“使用此来源”或登录操作                   |
| 当前平台未登录                           | 可通过“使用此来源”进入游客的公开浏览；需账号的操作提示登录 |
| 自动刷新凭据、启动恢复账号、收到账号通知 | 刷新对应平台状态，不擅自切换当前来源                       |
| 登录失败、取消、二维码超时               | 保持原当前来源                                             |
| 退出当前账号                             | 当前来源保留为游客状态，保存账号与凭据沿用既有规则         |
| 当前来源适配器停用或缺失                 | 显示不可用和切换入口，不悄悄切到另一个已登录平台           |

右上角入口显示头像和账号名，无账号时显示“未登录”；始终可点击打开。账号 Popover 标题下保留当前来源说明，各平台直接展示保存账号列表及添加／退出操作，省略重复的平台账号摘要和“使用此来源”按钮。点击已保存账号执行账号选择并切换；添加账号进入既有账号页，不另建一套登录弹窗。游客使用来源的入口保留在账号页及适配器设置中。

来源切换先完成有效性与持久化校验，再发布新的宿主来源修订号；失败保留原工作区，显示可重试错误。平台账号已登录但来源切换写盘失败时，应准确提示“登录成功，切换失败”，允许重试，不能谎报整个登录失败。

登录挑战绑定来源、页面／用户意图代次和适配器实例；用户开始另一平台登录或明确切换后，旧挑战不能抢回当前来源。已经安全保存的账号可以保留，但迟到回调只更新该来源账号信息。原页面退出应停止轮询，取消不能依赖前端 Promise 结束。

### 页面和播放连续性

来源驱动的音乐库、发现页及账号状态按新来源重载，旧响应不得覆盖。搜索保留关键词和类型，更新来源快照后重查；实体详情和历史导航保留完整来源引用，不把网易云专辑 ID 用在 QQ 详情请求中。返回某个平台详情不自动退出其他账号。

切换来源不停止当前音频、不清空混合队列。播放栏始终显示曲目真实来源；在“播放信息”中展示曲目来源、实际音源、实际音质及限制。需要平台收藏时，按曲目自己的来源账号与写能力判断，按钮不能仅因当前来源已登录而启用。

## 单音源服务接入

设置 → 适配器沿用 `SettingsCard`，区分“音乐平台”和“播放音源”两组。网易云、QQ 显示账号、能力与启停；音源卡片显示服务名、支持的曲目平台和音质请求、配置／密钥状态及启停，不提供平台登录入口。

为每个平台配置 `平台原生` 或已选定服务作为资源提供器，默认保留原生。初期不静默回退或跨平台替换；失败报告实际音源并允许重试或手动改选原生。这样资源提供策略可验证，后续回退策略不会藏在不同适配器内部。

提出的资源接口接收稳定曲目引用、必要元数据、请求音质、降级偏好、来源／账号／实例上下文，返回后端播放资源及实际资源提供器身份。支持平台必须明确声明；音源配置修订参与资源失效，切换服务取消旧预加载，不中断已交付音频。临时 URL、请求头及密钥不进入公开歌曲 DTO、持久队列或日志。

服务 API 密钥不是音乐平台账号，不交给平台账号选择逻辑；需要受控的后端凭据配置。响应、重定向、目录／域名权限、资源有效期、试听限制与预算继承现有边界。未知音质或完整播放范围不能凭请求参数宣称为已验证。需要音频认证头时先补受控传输；现有 URI 路径拒绝非空资源头。

## 实现归属与阶段

1. **统一身份与当前来源**：扩展共享来源／曲目模型、实际队列和导航 DTO，兼容已有网易云和本地数据；在 `features/music` 管理当前来源，在 `features/account` 复用账号入口；Rust 宿主 `music` 模块协调配置与代次，不让账号管理器承担页面导航。
2. **QQ 只读与登录验证**：新增独立 `adapters/qqmusic` 原生包，先实现单曲、搜索、详情、播放和登录，接统一契约；候选库见 [研判](../research/netease-qq-music-api.md)。未补个人曲库与写入前不能称完整适配器。网易云维持现有独立包，不为采用候选库而替换已有平台 SDK。
3. **QQ 完整业务**：复用成熟上游补用户资料、个人曲库、收藏、歌单写入与艺术家专辑等实际缺口；若必须自行实现上游已覆盖的功能，先说明必要性。平台不支持的可选能力报告 `unsupported`，不模拟成功。
4. **聚合搜索与切换**：宿主／统一客户端协调有界请求与作用域，`features/search` 保存聚合交付状态并复用列表、卡片和页面 shell；所有来源相关路径不得继续默认硬编码网易云。
5. **选定音源服务**：在许可和协议核验后接一个独立资源提供器，验证平台映射、音质、权限、寿命与预加载，再扩展服务。此阶段不包含本地聚合歌单、任意 JS 执行或自动跨平台替代。

`go-music-api` 可作为 QQ 个人歌单与喜欢读取的补充依据，仍缺 Profile、收藏与歌单写入、艺术家能力；其服务搜索会过滤部分付费曲目且等待所有来源，不沿用为宿主聚合调度。优先验证原生 QQ 组件补协议的方案，暂不引入 Go sidecar 或 FFI；具体覆盖、凭证身份差异与许可见 [Go 库研判](../research/go-music-api.md)。复制或改编实现前按实际许可核对通知和分发要求。

以上是实施分界而非本轮完成记录，源码研究与设计演示不能代替真实平台验收。

## 验收场景

### 实现进度（2026-10-12）

- 阶段一已开始：宿主独立保存当前来源、补充来源顺序与配置修订号，提供实时 IPC 和变更事件；设置入口支持修改角色与顺序，拒绝过期修订，写盘失败保留旧值，启动保留已停用或缺失来源。配置不改变账号、队列或已交付音频。
- 阶段一通用身份路径已接入：新增在线队列 DTO 保存完整统一曲目，实际曲目表按真实来源存储，播放解析按稳定引用路由。网易云桥接继续使用原 key／数字 DTO，本地路径与已有队列不重写；新平台使用完整引用 key，不同来源不误去重。菜单 DTO 和详情导航保留引用，统一详情入口不走网易云数字 ID；通用详情有独立游标和末尾续载。
- 宿主账号与来源流程已接线：明确登录／选择账号后以独立操作代次切换来源，先保存配置再发布事件；新登录、账号选择或手动来源操作使旧切换失效。启动恢复、账号刷新与退出不切换来源。二维码离页／刷新撤销宿主挑战，取消后迟到结果不能写入凭据。账号保存成功但来源写盘失败分别提示，保留重试入口。
- 工作区按当前来源加载音乐库与发现内容，停用／缺失时显示不可用及选择入口；详情保留来源引用，来源变化不操作队列或已交付音频。网易云继续使用已有完整界面，其他来源经统一收藏与推荐契约呈现。
- 聚合搜索宿主流程已接线：当前与补充来源并发首批、独立游标、到达后追加、引用去重、来源筛选和单来源重试；只挂载当前类型面板，歌曲沿用虚拟列表。每来源每类型最多保存 1000 项，达到上限显式提示并停止续载。来源／账号／实例／写入事件使查询重建，旧批次不再发布；底层在途请求仍沿用统一管理器期限及作用域检查，未增加 IPC 请求取消接口。源不支持某类搜索由该请求报告不可用，现有能力描述仍以 Search 组声明。
- 当前仍仅随包提供网易云。QQ 业务与真实双平台验收尚未完成，不能将宿主聚合调度或测试来源视为完整多平台上线。单音源服务接入按用户 2026-10-12 指示暂缓。ADR 0008 保持实施中。

本批验收：Windows 本地环境，前端 228 项测试、TypeScript／Vite 生产构建、Rust 宿主 `--lib` 148 项测试（3 项 ignored）以及 `format:check` 通过。新增回归覆盖交付顺序、独立游标／重试、跨来源去重、迟到批次、容量上限、来源意图覆盖、登录取消后禁止写凭据，以及账号通知先到时的来源切换失败提示。完整 Rust 集成测试另发现既有播放测试问题：无缝测试并行共享进程临时目录而相互删除文件，串行执行 21 passed、1 ignored；随后 HTTP seek 的 `range_without_declaration_seeks_forward_backward_and_paused` 报 `Failed to seek`。本批没有修改这些音频测试或播放核心，不将完整集成套件记为通过。尚未进行真实 QQ 登录、平台播放、macOS/Linux 实机验证或性能测量。

- 两来源响应快慢互换、部分失败和续载失败；已有结果可播放、顺序不重排、游标不丢失、空与失败可区分。
- 单曲、歌单、专辑、歌手均显式显示来源；来源筛选不切工作区；窄窗口、紧凑模式、深浅色、键盘操作及页面末尾不被播放栏遮挡。
- 两平台同时保存账号；登录／选择账号成功切换，失败不切换，刷新与迟到登录不抢回来源；退出保持游客，停用不清账号与队列。
- QQ 歌曲出现在网易云工作区时，详情、收藏、播放和预加载仍走 QQ 上下文；相同平台内 ID 去重，跨平台同名曲目不误合并。
- 来源／账号／适配器／音源变更后的旧请求与预加载失效；真实播放继续使用统一核心和系统媒体控制。查询和资源缓存隔离来源、账号及实例，不缓存临时 URL。
- 性能测量包括两来源并发首批耗时、首声、持续分页的内存峰值及后台占用；先报告 Windows 实测环境，再持续验证 macOS/Linux 编译与基本播放。
