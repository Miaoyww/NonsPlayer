# 缓存与本地音乐

修改资源获取、缓存设置或目录管理时阅读本文。这里定义复用边界；容量常量与已注册命令以对应实现文件为准。

## 便携版数据目录

Windows 便携包通过 EXE 同目录的 `portable.flag` 启用独立数据目录：配置、曲库和插件数据位于 `data/`，资源缓存位于 `data/cache/`，WebView（含展示预览）位于 `data/webview/`，临时 NCM 解码位于 `data/temp/`。账号与插件凭据使用 `data/credentials/` 内的文件，不访问系统凭据库；凭据不加密，移动目录时应妥善保管。目录不可写时明确失败，不回退到 AppData。安装版维持系统目录策略；便携版不自动读取或迁移安装版的数据。外部授权的音乐、下载文件继续位于用户选择的目录。缓存清理不删除账号凭据、设置和曲库。

## 设置中的占用与清理

“本地与缓存”将歌词缓存、其它缓存和日志独立分组。歌词的开关、容量、目录及清理仍使用 TTML 专用入口，不影响其它缓存或日志。

其它缓存按在线封面、查询与展示结果、在线歌单曲目列表、歌曲信息和插件编译缓存分别统计与清理。在线封面统计 `online-covers-v1/images/` 中持久化图片的实际去重字节与文件数，256MiB 为图片有效载荷预算，不包含 SQLite 索引文件；查询与展示结果包括非歌词查询和音乐库启动预览；歌曲信息指插件共享的公开元数据缓存。查询、展示结果和歌曲信息的内存占用按内容估算，不代表进程堆内存，也不包含组件当前持有的数据或图片解码内存。在线歌单统计关系快照的有效载荷估算，清理只删除快照与曲目列表关系，保留共享曲目记录、播放队列、本地曲库及本地歌单；前端派生查询与分页状态同步失效。旧在途请求不能在清理后回填旧封面、歌曲信息或歌单快照。

插件编译缓存按专属目录中的普通文件统计磁盘字节，清理与编译串行，已加载组件继续运行。清理不遍历目录链接，不触碰插件配置、存储或文件数据。日志单独统计本应用的会话与轮转文件：历史文件删除，当前日志文件清空后继续写入，因此清理后占用可能立即增长。日志和编译缓存统计均为读取时的文件大小；歌单清理不压缩共享 SQLite 数据库文件。

这些入口不清理本地封面资产、浏览器管理的音频缓冲、WebView 用户数据、下载文件或正在使用的播放资源。日志与其它缓存清理均不更改账号、设置或歌词缓存。

## 插件资源与歌曲信息

全屏播放器封面的复制与另存为使用元数据中的原图地址，不回退到缩略图；在线资源复用 Rust 封面缓存及其来源校验、容量与失效规则，本地只允许读取曲库封面目录。导出操作不加入查询缓存，单次只执行一项；保存保留原始字节及格式，复制通过保留 64MiB 分配预算的图片解码写入系统剪贴板，不额外限制宽高。在线封面下载和读取不另设单文件字节数上限，磁盘缓存仍按 256MiB 总预算校验与淘汰。本地封面导出不受在线磁盘缓存预算限制。用户保存的文件独立于资源缓存，取消保存不产生文件。

插件配置默认值与用户覆盖值按修订号读取，不加入查询缓存；写入通知刷新相关配置，清理资源缓存不删除配置。独立数据目录为应用数据目录下的 `plugin-data/<id>`，文件 IO 在阻塞工作线程执行。停用关闭实例句柄，撤销授权关闭对应句柄；卸载默认保留配置、键值与专属数据，主动关闭保留选项后才清理。外部授权总会撤销，外部内容不删除。接口与限额见 [插件配置开发](plugin-configuration.md)。

插件 React SDK 仍通过 `nativeCall` 调用 scoped IPC，封面沿用 `useCoverSource`／`runtime_cover`。方法调用、权限检查、生命周期、存储与插件列表不加入查询缓存：每次必须验证当前加载代次，不能由缓存绕过禁用或权限判断。

子进程与独立窗口操作同样不进入查询缓存，每次验证插件权限和加载代次；进程输出仅保留有界内存缓冲，不写资源缓存。主 WebView 的后台释放开关作为宿主设置持久化，释放主界面不撤销子进程或独立窗口；停用、重载、实例故障和退出时清理它们。

`accounts.credential-read` 仅交付给显式授权 `account:credentials` 的活跃插件，按来源分块读取不透明凭据和账号／实例上下文，每块最多 4096 字节，不缓存、不写插件存储。下载插件每次解析资源前读取，并在发布前核对账号代次；切换账号或退出后旧下载结果不得发布。`files.resolve/play/open-directory` 每次核对根目录授权与路径；已下载文件继续独立于播放缓存，列表复用宿主组件与封面缓存，不自动添加曲库目录。

插件设置的 ZIP 拖入与文件选择共用 `plugin_install`，安装后沿用 `plugins-changed` 更新列表；搜索仅筛选当前已安装列表。`plugin_open_folder` 由宿主直接打开插件管理器的安装目录，不接受前端路径参数，不加入查询缓存。

WASM 无法调用 WebUI 的 `nativeCall`，因此 `plugins/music.rs` 的 `SongService` 为 `music.read-track` 提供共享的 Rust 运行时缓存，以完整 EntityRef 为键，底层经统一 MusicService／AdapterManager 路由到对应适配器并复用各自连接池；旧数字歌曲方法已移除。成功结果 TTL 10 分钟，不延长命中 TTL；128 条上限，每个公开 DTO 最多 64KiB，有效载荷估算上限约 8MiB。查询串行合并重复请求，失败不缓存、不持久化，单次网络预算 3 秒。

通用剪贴板读取与变化事件是实时能力，不加入查询缓存；待处理原文有 16KiB 上限，消费或停止监听后清理，不持久化。通用 HTTP 请求用于插件自己决定的资源获取，不进入宿主网易云查询缓存，也不携带宿主账号凭据；响应不缓存。插件需要缓存业务资源时使用独立存储或文件能力，自己管理容量、过期与失效。宿主只复用有界连接池；接口预算见 [插件接口](plugins.md)。

单曲缓存命中和写回同时检查适配器启用、实例代次与旧会话桥接代次，停用或重载不能命中旧条目；扫码登录成功、会话失效和退出推进账号代次并清空该缓存；旧请求不得写回。缓存只保存公开歌曲元数据，不提供 Cookie、临时播放地址或本地文件路径。插件专属键值存储位于 `plugins.sqlite3`，不属于可清理资源缓存；关闭插件保留数据；卸载默认保留分区，用户主动关闭保留选项后才删除。动态 UI／资产使用加载代次 URL 和 no-store，禁用后拒绝新资源请求；浏览器已经加载的 ESM 模块记录不能主动回收。

## 音乐适配器管理

### WASM 编译结果缓存

外部音乐适配器与功能插件共用 Wasmtime 编译结果缓存，位于应用缓存目录的 `wasm-compiled-v1/`；便携版使用 `data/cache/wasm-compiled-v1/`。缓存只包含编译后的代码，不保存 Store、账号、凭据、权限或运行中的 guest 状态。缓存键与兼容性检查由 Wasmtime 处理，源码、引擎版本、目标及编译配置变化后重新编译；损坏条目回退编译，缓存目录不可用时记录警告并继续无缓存加载。每次加载仍验证描述符，每次调用仍新建 Store 并执行原有权限、取消、代次和时间预算检查。

容量采用 Wasmtime 原生 **512 MiB 软限制**及后台回收，可能暂时超过该值；宿主不另行扫描或强制裁剪。它属于运行时基础设施缓存，不受 TTML 缓存目录、开关或清理控制；删除该编译缓存目录后，下次加载自动重建。编译共享两个 Rayon 工作线程，同一时间编译一个组件；编译在阻塞工作任务执行，已编译组件继续在内存复用，不在业务调用中重新编译。

调试构建仅对 Wasmtime／Cranelift 的主要编译器依赖开启 Rust 优化，应用自身继续保留原有调试配置。加载诊断分别记录引擎创建、文件读取、编译／缓存命中及初始化耗时；缓存命中不能代替初始化和权限校验。冷、热加载性能以相同组件和构建配置实测，不将编译耗时直接等同于总启动耗时。

### 启停与账号

账号卡片通过 `adapter_list` 获取来源，`music_current_account` 与 `music_accounts` 实时读取当前选择和保存账号，不缓存、不返回凭证；账号来源切换丢弃旧响应。退出仅取消当前来源的选择，保留记录和系统凭证；删除账号才清理凭证。两种操作沿用账号代次和 `music-account-changed` 通知，使旧请求和查询缓存失效。

聚合账号登录页沿用同一账号读取和事件路径，仅为当前选择的适配器生成二维码并轮询；切换来源或离开页面时停止轮询、丢弃旧登录结果。账号头像通过 `useCoverImageSource` 复用有界图片缓存与图片失败回退策略。

适配器列表、启停及重载经 nativeCall 实时调用，不加入查询缓存。`musicAdapterEnabledV1:<source>` 是设备设置，保存在现有 SQLite settings，停用重启后保持；账号切换与缓存清理不删除它。保存失败不改变运行启停。成功变更发出 `adapters-changed` 与 `music-changed`，清理查询缓存并推进实例代次；nativeCall 与插件 Rust 歌曲缓存继续在命中/发布时复核来源上下文，旧查询及预加载不能发布。停用保留账号和队列，歌词磁盘缓存不删除，既有资源/本地缓存策略继续有效。

## 运行时缓存的接入

### 收藏状态

WebUI 的收藏状态按来源共享，以 `nons:music:favorites:v2:<source>` 保存最多 100000 个 ID 和最后完整读取成功的时间，不按账号分区；序列化文本上限 4Mi 个 UTF-16 码元。启动先展示完整快照，再经统一音乐客户端后台校准，正常有效期 10 分钟。窗口聚焦、恢复可见和可见期间的定时检查仅在到期后发起读取；失败退避 30 秒，歌曲菜单可以主动重新读取，同一来源的在途读取合并。账号变化保留共享展示并重新校准，旧会话的读取不能发布。

首次读取尚未完成时，分页中已取得的 ID 只能确认“已收藏”；没有完整快照或单曲操作证据的其它 ID 为“待确认”，不能当作未收藏或发起收藏写入。失败保留最后成功快照与已确认的正例，部分分页不作为完整快照持久化。音乐库已确认属于当前账号的喜欢歌单时，可用已加载的预览与成员补充正例，不据此推断缺失歌曲未收藏，也不额外请求无关首页。单曲写入成功后立即更新同一来源的列表、播放栏、菜单和快捷键；早先开始的校准不能覆盖该次操作。平台歌单写入与系统收藏变化事件失效相关读取并触发重新校准。

未知状态显示省略号、禁止写入且不声明已收藏或未收藏；已有状态在后台刷新或失败时继续展示，歌曲菜单提供“重新读取收藏状态”。

### 浏览器音频执行端

所有平台的 WebAudio 继续由 Rust 播放 Actor 管理队列、资源解析、错误跳过和系统媒体控制；主 WebView 执行 `audio` 与 AudioContext 播放并回传实际进度与状态（播放进度补偿输出延迟，停止确认使用原始媒体位置）。控制与反馈经主窗口实时 IPC，携带意图序号和反馈序号，拒绝旧资源、旧操作及乱序反馈。

音频通过仅绑定 `127.0.0.1` 随机端口、每次加载生成随机句柄的流式入口访问，只提供 Actor 已解析的当前资源与一个过渡资源，不接受前端指定文件路径、上游地址或账号头。在线请求复用当前解析结果，通过 reqwest 连接池按需流转并转发 Range；本地与 NCM 解码临时文件通过 tower-http 文件服务读取并支持 Range，临时文件保留至响应释放。最多四个并行音频请求，响应使用流式背压与 `no-store`，不把整首音频读入 IPC 或新增磁盘缓存；停播与手动切歌撤销句柄并取消旧响应。交叉淡入淡出开启后，最多提前 30 秒解析和预加载一首后继歌曲，失败最多尝试三次、间隔至少 5 秒；浏览器确认后继开始播放后才推进队列与历史，前一首资源在淡出完成或时长加 1 秒的期限后撤销。最多两个存活音频资源和播放器，不使用整曲 PCM 解码缓冲。浏览器自己的媒体缓冲由 WebView 管理，不能视为宿主既有播放缓存，不支持的格式无法播放。输出设备保存浏览器设备标识；设备设置不进入资源缓存。应用保留主 WebView，确保隐藏窗口与暂停后的系统媒体控制可继续播放。

### 单曲歌词纠错

全屏播放器菜单的“歌词来源”打开纠错弹窗。QQ／网易云候选搜索和预览通过 `nativeCall` 与既有歌词服务执行，不通过音乐适配器搬运歌词业务；搜索每次最多 20 项，共用两个并发任务和 6 秒请求预算。预览的 QRC 解析失败时仅重取同一候选的 LRC，不切换录音版本。

选择的来源、歌曲 ID、展示元数据及 ±60 秒的单曲偏移，以曲目 key 摘要为设置键保存在原 SQLite settings，不存账号或临时地址。它们是用户设置，清理歌词资源缓存不会删除，重启后按原曲目身份恢复。歌词正文继续使用既有 64MiB／2000 项运行时缓存，确认缺失约 24 小时，成功 10 分钟；网络失败不缓存为缺失，QQ／网易云正文继续不持久化。显式选择优先于自动来源和本地歌词来源偏好，不改歌曲身份或音源，暂不可用时保留选择并提示刷新。

保存／恢复自动匹配接入歌词设置代次、运行时查询失效与 `lyric-correction-changed` 事件；后台自动刷新不能覆盖手选版本。行和逐词时间轴共同应用偏移，CUE 本地歌词先截取分轨范围再偏移，音频时间轴保持原样。切歌或新选择后拒绝旧查询和预览结果；Android 媒体歌词复用相同选择与偏移。

在线歌词定位沿用曲目真实来源，与所选音源分开。适配器可在 `MusicTrack.lyricIdentifiers` 提供最多 8 个同平台带类型 ID；缺省时，歌词服务仅在能识别主引用 ID 类型时兼容读取。AMLL 按 `netease / qqmusic / applemusic / spotify` 选择对应目录；多 ID 和镜像合计最多 3 次请求，共享 1 秒预算。QQ 有可用本平台 ID 时直接取词，不搜索其他候选；缺少可用 ID 才进入既有元数据搜索。

AMLL `amll:v2:<摘要>` 的摘要包含平台、ID 类型和值及有效模板；QQ `exact-v4` 与 `search-v4` 分别隔离精准与搜索结果，QRC/LRC 再分别建键，摘要保留完整曲目与歌手分隔符。WebUI `track_lyrics` 参数中的 `trackVersion` 区分元数据与定位标识变化，后端始终读取曲库中的权威曲目。手动刷新、配置变化推进既有缓存代次；后台事件携带发起请求的曲目，服务端和页面均拒绝旧身份结果。新键不强制删除旧 TTML，由原容量与过期规则淘汰；本地绑定及读取策略保持原状。

`set_lyric_endpoints` 增加可选 `platform`（缺省网易云），将分平台模板保存在 `lyricEndpointsV2`；未配置时，网易云继续读取旧 `lyricEndpoints` 数组，其他平台使用官方目录。旧数组不会用于 QQ 等平台。模板变更同步失效运行时结果和在途写回，新模板进入 AMLL 键；不增加镜像设置页面或独立缓存。网络、解密、解析失败走短期退避，只有全部适用查询明确缺失才缓存约 24 小时的无结果。

独立音源搜索不进入查询缓存；音源实例、查询条件变化后拒绝旧页，封面沿用显式域名授权及既有缓存。音源取址不保存普通 URL 缓存，预加载沿用最多 60 秒资源租约并复核平台账号／实例及音源实例代次。当前队列条目的手动选择仅存在播放 Actor 内存，移除、替换队列和重启后清理；契约与范围见 [独立音源适配器](resource-providers.md)。

完整平台适配器作为其他平台的音源时，复用上述取址和资源租约流程，并使用提供者自己的账号上下文、实例代次与解析并发预算。原曲平台和提供者的账号／实例在请求中持续复核、资源交付和预加载消费时再次复核；任一失效即拒绝旧结果。描述符及功能描述仍通过实时适配器列表读取，不新增查询或磁盘缓存。

整组播放请求先以 `Command::Collection` 交给播放核心，核心持有有界的单个歌单准备任务和请求代次。详情页、专辑页与喜欢歌曲入口优先传入已加载的首曲 key，立即从曲库核对并进入 Loading／音源解析，完整歌单在后台补齐；无已知目标时先发布 Loading，按 1 首请求取得首曲并启动，再后台获取完整队列，不等待后续页面。新队列、跳转、停止、清空、暂停或队列编辑会取消旧准备，迟到结果不得替换队列或发布错误；补齐前复核来源／账号作用域。补齐只更新队列与当前索引，保留音源、进度和播放 revision；失败保留已选曲目并报告歌单准备错误。临时单曲队列准备期间暂停无缝预加载，避免提前绑定错误的下一首。歌单准备继续沿用 MusicService 的 1000 首上限与 12 秒预算，不缓存临时播放地址。

前端资源读取统一调用 `app/src/lib/player.ts` 的 `nativeCall`。`app/src/lib/runtime-cache.ts` 使用 lru-cache 实现 10 分钟 TTL、LRU 容量限制和同键并发请求合并；读取不延长 TTL。页面组件保留展示状态，资源缓存由统一入口管理。

- 查询键由命令与排序后的参数组成，搜索词、分页偏移、收藏类型和 ID 都属于键。`refresh` 是刷新指令，从键中排除，调用前删除对应结果。
- 搜索建议 `search_suggestions`（最多 5 条）和分类搜索 `search_collections`（每页 30 条）复用统一查询缓存与账号失效规则；关键词、类型和偏移进入键。建议输入防抖 250 毫秒，输入变更、失焦或切换本地搜索后丢弃旧响应，失败不缓存且不阻塞直接提交关键词。
- 音乐库预览、歌单/专辑/艺人列表和详情、听歌记录、搜索、本地曲库、喜欢歌曲 ID、歌曲详情和歌词进入查询缓存。账号切换或退出清空查询缓存，包括未完成请求；过期查询重新获取。首页可通过 `peekMusicLibrary` 先展示旧预览，再获取新结果。
- 歌手／专辑详情 `music_entity_detail`、歌手专辑 `artist_albums` 和歌手歌曲 `artist_tracks` 复用查询缓存，类型、ID 与分页偏移进入键。歌手最新发布与专辑 tab 共用首批专辑；历史歌曲缺少结构化 ID 时，仅点击名称后查询 `song_information`，不逐行预取。本地歌曲通过本地艺术家/专辑索引跳转，绑定的网易云 ID 仅用于歌词关联。
- 收藏专辑接口不提供发行日期；缺少日期的专辑卡片仅在进入可见区域后通过 `music_entity_detail` 补齐，与专辑详情页共用缓存和并发合并。列表已提供日期时不补查，收藏时间 `subTime` 不作为发行日期；补查失败保留未知状态，再次进入页面可重试。
- 封面通过 `useCoverSource` 获取，同一 URL 的内容使用独立图片缓存。在线封面由适配器提供 `small / normal / large / exlarge / original`，宿主仅按场景选择，不生成缩放参数：列表、播放栏、头像与侧栏用 small，卡片用 normal，详情头图与 FM 用 large，全屏主封面用 original，列表封面在视口附近才加载；全屏播放器封面使用 eager 模式，绕过可见性检测和浏览器懒加载，避免进入动画期间停留在占位状态。账号切换保留这些公开图片。失败尝试更小档位，最后回退原图。
- WebUI 封面仅缓存最终 URL 对应的本地资源链接和来源授权标识，不保存图片字节；元信息最多 512 条、10 分钟 TTL、48MiB 估算预算，按字符串长度计重，不对图片内容执行 JSON 序列化。音乐查询缓存仍为独立 48MiB，继续按序列化内容计重。模糊背景用 small，仅在启用、活跃且可见时加载。封面与专辑背景通过 `useCoverImageSource` 接收图片加载错误：缓存图片解码／加载失败时删除 WebUI 与原生对应缓存键并尝试更小档位，最后回退原图；原图主动加载失败时反向尝试缩略图。Tauri 内远程封面的全部候选均经 `nativeCall('runtime_cover')` 获取，不向 WebView 回退远程直链；候选和资产修复均限制重试次数，耗尽后显示占位并结束加载状态。重新激活或重新打开页面会重试获取，不在错误回调中循环请求。专辑背景等图片加载成功后，将同一个图片元素交给 AMLL，避免独立获取与重试；切歌、隐藏或关闭后丢弃旧加载结果并释放背景渲染器。原生 `runtime_cover` 返回独立在线封面缓存内的绝对文件路径，`nativeCall` 转为 Tauri asset 链接后交给 WebView 加载。后台刷新成功通过共享的 `runtime-cover-updated` 监听按 URL 失效元信息并更新在用图片；监听建立后才发送首次读取，迟到结果不得覆盖新资源。磁盘清理、淘汰或损坏导致资源加载失败时，同一候选只重新获取一次，之后才尝试其他尺寸；多个组件合并同 URL 修复，避免循环。普通浏览器预览仍可用直链展示图片，其跨域读取能力由上游响应决定。
- `runtime_cover_access` 在 WebUI 缓存读取前与交付前实时核对已启用适配器的封面域名及实例状态，不进入查询缓存。`runtime_cover` 在原生缓存命中及网络交付前同样复核，不再硬编码网易云主机。`runtime_cover`、封面导出与 Android MediaSession 共用原生磁盘封面服务，安装版位于应用缓存目录的 `online-covers-v1/`，便携版位于 `data/cache/online-covers-v1/`。图片按内容 SHA-256 去重并原子发布，SQLite 索引仅保存 URL 摘要与资源元信息，不保存账号或明文 URL。图片总预算 256MiB，按最近访问回收；新鲜期 24 小时，重启后复用新鲜文件，读取过期项时先返回旧文件并后台刷新，刷新失败保留旧图、至少 30 秒后才能再尝试后台刷新。Rust 仅合并在途下载并保存有界任务元信息，不常驻缓存 base64 图片；沿用宿主 HTTP 连接池、8 个并行下载和单张 8MiB 下载上限，文件与索引 IO 进入有界阻塞任务。命中时核对普通文件、长度与内容摘要，损坏项重新获取；损坏的专属 SQLite 索引可重建。清理与单 URL 失效推进缓存代次，旧在途下载不能回填或交付；仅清理受控在线资产，不触碰本地封面。WebUI 图片解码失败通过 `runtime_cover_invalidate` 同步清除原生缓存。Windows SMTC 与 Android 媒体封面选择 exlarge，由适配器决定像素与地址。Windows SMTC 继续使用系统 URI 读取；Android 传递缓存文件路径，在单后台线程读取，最多保留一个待处理请求，切歌和释放后拒绝迟到结果，不经 WebUI 或 mobile-plugin IPC 传输 base64 图片。本地封面仅读取宿主封面目录中的既有文件，不套用在线图片的字节数限制。
- Android 系统歌词复用既有歌词服务、缓存与 AMLL 解析，不新增持久缓存或独立网络来源；原生只保留当前曲目的行时间轴，最多 5000 行、正文及辅助文本合计 1MiB、每个文本字段最多 4096 字节。切歌后清空并拒绝旧曲目结果，正常播放以 250ms 检查当前行，仅行内容变化时发布元数据，暂停停止计时。以上为实现上限，尚非后台耗电实测结论；vivo 卡片显示仍未通过验收。
- 查询和封面分别设条目数与序列化大小上限。大小是 UTF-16 序列化长度估算，既不是堆内存测量，也不包括图片解码、组件持有的数据或正在进行的请求。
- 发现页歌单、分类、私人雷达信息和每日推荐／FM 曲目复用同一查询缓存；歌单的分类、排序和分页偏移进入键。账号切换清空个性化结果；FM 打开及播放到队列倒数第二首时以 `refresh: true` 获取新批次，补歌跟随全局播放快照，与发现页生命周期无关；同一 FM 会话串行补歌，队列编辑后由播放核心作废会话并拒绝旧批次追加，失败不循环重试，可手动重试或切到下一首后重试。FM 队列沿用 1000 首上限，自动补歌超限时只淘汰已播放的历史。成功“不喜欢”使推荐曲目缓存失效，失败保留原结果。推荐歌单首批最多 30 条，后续按每页 30 条追加全部分类的热门歌单（列表偏移 30 对应热门接口偏移 0）；按歌单 ID 对当前查询展示结果去重，不修改缓存页。广场每页 30 条，推荐曲目最多 100 首，封面继续通过 `Cover` 懒加载与统一图片缓存读取。
- 查询失败、部分失败的喜欢预览、未取得歌词的空结果可重试。登录轮询、会话检查、设置读取、播放命令及临时音频地址直接执行；播放资源由播放核心按需解析。
- 收藏歌曲或删除歌单歌曲成功后，资源缓存仍按写操作规则失效；已打开的在线歌单把刷新代次与查询身份分开，后台重新读取已加载的分页范围，期间保留歌曲、详情和搜索／排序状态。完整结果返回后按歌曲 key 与元数据对比，复用未变化的歌曲对象和虚拟行标识；新增、删除、重排和元数据变化按新结果更新，失败保留旧列表并允许重试整个已加载范围。切换歌单或账号仍立即隔离旧查询，不沿用上一查询的展示状态。
- 发现页一言通过 `nativeCall("discovery_hitokoto")` 读取，复用查询缓存的 10 分钟 TTL 与并发合并。使用独立于网易云账号的公开 Hitokoto 接口，单次请求限时 3 秒、响应最多 16KiB；错误和无效内容不缓存，由页面显示默认文案，再次进入可重试。
- 音乐库喜欢卡片按顺序尝试预览中的前两首歌曲，复用 `loadLyrics` 与歌词来源设置；最多保留 32 组会话内歌词摘录（序列化估算合计 256KiB、单项 8KiB），键包含候选曲目版本和歌词来源偏好。重开时先显示已缓存的摘录，再照常读取歌词；成功后更新摘录，失败时保留旧摘录。无可用歌词或读取失败后查询同一 `discovery_hitokoto` 缓存。全部失败显示缺失／读取错误与一言失败原因，页面离开或候选歌曲变化后停止后续请求并丢弃旧结果。

接入新功能的步骤：

1. 从 `nativeCall` 调用现有资源命令；资源读取新增命令时，在 `cachedCommands` 中登记，并确认所有影响结果的参数进入键。完成标准是重复及并发读取只触发一次底层请求。
2. 歌单添加歌曲成功后使喜欢歌曲 ID、音乐库预览、收藏列表和歌单详情失效；编辑信息成功后同时失效发现页歌单与实体详情，删除成功后失效发现页歌单。收藏弹窗复用按每页 30 条读取的 `library_collections`，分页遍历自己的歌单并按 ID 去重，仅渲染视口附近的条目。歌单移除歌曲成功后使收藏状态、音乐库预览、收藏列表和歌单详情失效；移除队列项只更新播放状态，不影响资源缓存。写操作成功后在 `nativeCall` 的影响表中登记相关读取命令。完成标准是成功写入后获得新数据，失败保留原缓存，写入前的未完成请求无法重新填回旧数据。
3. 涉及账号切换时复用 `resetAccountCache`；涉及后台更新时复用既有事件失效路径。完成标准是旧账号结果不会进入新账号页面。
4. 给刷新入口传入 `refresh: true`，或显式使用 `invalidateNativeCache`。资源适用本文已有策略时复用这一入口；确有不同生命周期时，在本文记录原因、容量与失效规则。

快捷键开关和绑定以 `nons-shortcut-settings` 保存在 WebUI localStorage，默认关闭、六项绑定均为空；启动恢复注册，停用解绑但保留绑定。注册失败先清理部分注册再恢复旧绑定，成功后才保存，录入与清除绑定自动生效，无需手动保存。绑定仅接受一至三个修饰键与一个普通键，旧单键或无效绑定恢复时清空；录入期间串行解绑，结束或离开页面后恢复。它们属于用户设置，不加入资源缓存；收藏复用账号入口与既有写入失效规则。

顶部网易云搜索历史以 `nons-search-history` 保存在 WebUI localStorage，只记录实际提交的非空关键词，去重后按最近搜索顺序保留 10 条；重复搜索置顶。本地曲库搜索不写入此历史。历史属于设备上的用户数据，不加入资源查询缓存，不随账号切换或缓存清理失效；存储不可用时在当前会话内保留，恢复时忽略损坏或无效记录。

歌单侧栏复用 `library_collections` 的分页与统一资源缓存，打开时重新读取，创建歌单沿用写操作失效规则。最近打开的在线歌单以 `nons-recent-playlists:<userId>` 按账号存入 WebUI localStorage，重复打开置顶，最多保存 20 条，侧栏显示最近 2 条；切换账号不把上个账号仍显示的详情记入新账号历史。此历史属于用户导航数据，不加入资源查询缓存，清理缓存时保留；恢复时校验记录并丢弃损坏数据，存储不可用时保留当前会话记录。

播放栏显示方式以 `nons-playback-bar-mode` 保存在 WebUI localStorage，默认折叠式，可切换常驻式或关闭；存储不可用时在当前会话内保留，损坏或未知值回到默认。此项属于设备界面设置，不加入资源缓存，不随账号切换或缓存清理失效。随机播放开关与有界随机索引顺序随播放快照保存；不改变歌曲列表顺序，恢复时校验索引完整性。

播放进度沿用 SQLite `player` 快照，每 5 秒保存一次，正常退出时再次保存；属于播放持久状态，不加入查询缓存。启动恢复当前歌曲与进度并保持停止状态，点击播放后重新解析资源，在暂停预备完成后定位再出声；已播完的歌曲从头播放。切换歌曲从零开始；恢复时校验当前索引并按已知时长限制位置，未知时长保留上次管线测得的时长。加载与待定位期间不让管线的初始零位置覆盖待恢复进度。

## 歌词运行时与磁盘缓存

更新状态、更新清单与遥测设置通过 `nativeCall` 直接读取，不进入音乐资源查询缓存。签名更新包仅保留一个受 512MiB 上限约束的临时文件，安装或正常退出时失效，不参与音乐缓存清理。匿名遥测安装标识与开关保存在 SQLite settings 中，属于用户设置，音乐缓存清理时保留；启动事件只在内存中重试，不写入磁盘队列。

Rust 歌词服务位于 `lyrics.rs`。所有歌词格式的运行时结果保存在曲库连接的 SQLite TEMP 表中，使用内存临时存储，成功结果 10 分钟过期。已确认缺失的标记保留 24 小时，网络错误只退避 30 秒；这两项沿用歌词来源约束，均不写入磁盘资源缓存。

全屏歌词显示状态同时绑定歌曲 key 与播放核心的 revision；切歌或重新播放时，第一帧即隐藏上一播放代次的歌词。查询完成、错误与后台更新写入前读取实时播放快照进行核对，不依赖 React effect 的清理时机；本地与流媒体歌曲即使标题相同也保持独立。WebUI 查询缓存继续按歌曲 key 与来源跳过参数区分。

全屏歌曲菜单直接显示已应用歌词的来源；刷新复用 `loadLyrics`，在线路径传入 `refresh` 清理对应缓存并推进后端代次，本地路径每次重读文件。手动刷新推进界面请求代次，旧查询不能覆盖新结果；刷新期间保留已有可用歌词并禁用重复刷新，切歌或修改来源后丢弃旧刷新交付。收藏、复制和详情复用 `SongActionsProvider`，平台收藏只作用于真实网易云曲目，本地绑定 ID 不作为流媒体歌曲身份。

全屏播放器首次打开时按需加载；封面、控制区与歌词区同步进场，AMLL 渲染器模块与歌词查询并行加载，歌词就绪即初始化和显示，不等待进场动画结束；仅在数据或渲染器模块仍未就绪时显示加载占位。动态背景首次启动仍延后至进场动画完成。关闭时暂停歌词帧循环、进度订阅和背景动画，保留当前这一份页面、歌词 DOM 与背景画布，退场完成后隐藏并禁止交互；再次打开复用实例，不逐次累积。关闭期间不发起歌词查询，旧在途结果不能发布；切歌或元数据、来源设置、艺术家分隔符变化后不得显示旧歌词。

同一播放代次的在线歌词在 10 分钟内且查询缓存未失效时，重新打开直接复用已解析行，不再重复取词和解析。缓存失效或到期重新验证时保留仍适用的显示内容；手动刷新、歌词纠错和本地歌词读取继续执行原路径，本地模式每次重新打开仍重读文件。隐藏窗口时仍沿用原渲染暂停与背景释放规则。歌曲存在时固定两栏布局，不因加载、缺失或模块下载改变封面位置。保留实例会增加关闭后的内存占用，实际 WebView 帧率与内存仍需实机验证。

TTML 持久化统一由 `ttml_cache.rs` 的 `TtmlCache` 管理。`cache_result` 在同一锁内检查请求代次、更新运行时结果并按开关写入 TTML。清空、配置变更及手动刷新推进代次，旧网络请求不能重新填充已清空的缓存。磁盘写入失败不阻塞在线歌词回退。

磁盘缓存只保存有效 TTML，当前由 AMLL 在线查询产生；QQ QRC/LRC 与网易云 LRC/YRC 留在运行时缓存。在线歌词继续复用现有运行时和 TTML 磁盘缓存。

`lyricSources.localSource` 保存本地歌曲的“本地／在线”来源选择，旧设置缺少此字段时默认在线；流媒体歌曲始终走在线入口。本地与在线之间不自动回退。`local_track_lyrics` 经 `nativeCall` 实时读取，不进入 WebUI 查询缓存、Rust 运行时歌词缓存或 TTML 磁盘缓存，每次加载重新读取音频内嵌歌词及同目录同名 LRC。内嵌文本不可用或解析失败时可跳过内嵌文本再次读取 LRC，两个本地读取阶段均不调用在线服务。普通音频标签读取跳过音频属性和封面，NCM 复用已有流式解密标签读取。正文上限 2MiB，UTF-16 解码后的 UTF-8 文本同样检查上限，最多两个并行阻塞读取任务。文件更改在下次读取时生效，暂不主动监听歌词文件。来源选择变更沿用现有设置保存与在线缓存代次失效；界面同时核对播放 key、revision 和来源设置快照，拒绝迟到结果及不适用的后台在线更新。

QQ 和网易云搜索歌词缓存键使用完整曲目元数据与本次艺术家分隔符配置的 SHA256，标签、绑定或分隔符变化不会复用旧匹配结果；QRC 优先路径使用 `qq:qrc-v3:`，前端解析失败后的 LRC 路径使用 `qq:lrc-v3:`，网易云搜索使用 `netease:search-v1:`，避免 QRC 解析失败时重新命中同一内容。`skipQrc` 进入 WebUI 查询键；手动刷新同时清理两种 QQ 路径、AMLL、网易云 ID 取词与网易云搜索路径。搜索结果连同匹配分存入既有有界运行时缓存，沿用 10 分钟成功期、24 小时确认缺失期、网络错误仅退避 30 秒及请求代次失效；低于 80 分的 QQ 成功结果保留并与网易云备用结果比较，不记为缺失。成功结果缓存 10 分钟，过期内容立即显示并后台刷新。确认未匹配到候选曲目或无歌词时缓存 24 小时，搜索/取词网络错误、解码错误和超时只退避 30 秒，然后继续网易云；QRC 失败后先尝试匿名 GetPlayLyricInfo，再回退旧 LRC；已有 QRC 仅补充缺失译文与发音，不替换逐词原文，补充后的总正文仍限制为 2MiB。补取预算在 QQ 总计 6 秒内，为旧 LRC 保留最多 1400 毫秒；有可用 QRC 时预留交付时间，避免补取超时丢弃原文。QRC/LRC 优先路径分别使用 v3 缓存键，避免复用旧回退链产生的纯原文。任一 QQ 路径成功的结果按成功结果缓存。来源设置以 `lyricSources` 持久化；成功更改推进缓存代次、清空运行时歌词及退避状态，并通过 `nativeCall` 使 WebUI 的所有 `track_lyrics` 结果失效。已有 TTML 磁盘文件保留，关闭 AMLL 时跳过读取；旧请求不能重新写入缓存或覆盖新设置下的显示结果。全屏歌词与音乐库摘录在来源开关变化时重新取词。

用户选择的是缓存父目录，应用使用专属目录：

```text
<选择的目录>/nons-cache-v1/
├── index.sqlite3          # 来源、格式、过期时间、访问时间与字节数
└── lyrics/ttml/
    └── <SHA256(缓存键)>.ttml
```

默认父目录采用系统应用缓存目录。容量默认 64MB，可设置 1–4096MB，另设 2000 条记录上限，达到上限按最久未使用淘汰。占用统计指 TTML 内容字节数；小型索引数据库另占空间。清空和迁移只处理索引中的歌词文件，用户选择的父目录及原始音频文件保留。

TTML 新鲜期为 10 分钟，过期仍可立即显示并后台更新；更新失败保留旧内容，以支持离线读取。关闭磁盘缓存停止持久化读写，已有文件保留，运行时缓存继续使用。更换目录迁移已有有效 TTML，规范化后的同一目录不迁移。不再创建或迁移历史 `lyric_cache` 表；已有旧表保留但不读写，旧缓存未迁移的歌词按当前策略重新获取。

本地音频的内嵌封面是曲库导入产生的元数据资产，沿用独立 `covers` 目录及既有容量限制，不属于此 TTML 清理入口。音频通过播放管线传输，本次不持久化歌曲音频。

## 本地目录与曲库

字体选择通过 `nativeCall("system_fonts")` 按需读取系统字体族名，使用 font-kit 的平台后端，不读取字形数据、不复制字体文件。两个选择器共用既有 WebUI 运行时 LRU（10 分钟 TTL、512 项和 48MiB 上限），失败不缓存；“重新读取”跳过旧缓存，安装字体后重新打开设置或重启可在缓存过期后刷新。应用字体和歌词字体以 `nons-font-settings` 保存在 WebUI localStorage，启动渲染前恢复；恢复默认不删除资源缓存。字体卸载或缺少字形时使用系统后备字体，保留用户选择。

`LocalFolders` 统一保存最多 32 个目录。桌面用 notify 递归监听文件变化，Android 通过 `tauri-plugin-android-fs` 选择 SAF 目录并保存持久授权。启动与新增目录触发后台扫描，Android 回到前台也触发扫描；扫描请求合并后串行处理，音频大小、修改时间及封面目录签名均未变化，且引用的生成封面资产有效时跳过标签解析。源图片候选的路径、大小和修改时间参与目录签名；封面资产缺失、损坏或摘要不符时重新提取。扫描错误保留此前索引，各平台均可手动重新扫描。

`local_origins` 记录曲目与导入来源的多对多关系：桌面管理目录使用规范化绝对路径，Android 使用包含授权标识与相对文件名的内部文档位置，单独打开的文件使用独立来源。完整扫描结束后移除该目录下已不存在的记录；移除目录清理其来源关系，Android 同时撤销本地音乐对该目录的访问，已打开的播放流也停止读取。其他来源仍引用的曲目继续留在曲库；桌面播放队列持有的曲目保持可播放，原始文件保留。不再启动回填历史导入来源；当前导入入口显式保存来源关系。

扫描、标签、封面、CUE 和本地歌词共用本地读取入口；桌面读取普通文件，Android 根据已授权的 SAF 文档位置打开文件描述符，不把 `content://` 当作文件路径拼接。Android 普通音频通过既有受控流式桥接按需读取，支持 Range 和独立定位，不复制整首音频；文件提供器需支持可定位读取。SAF 查询缓存只存活于单次读取或扫描，最多保留 4096 个文档元数据和 16 个目录（目录缓存合计最多 4096 项），离开读取范围后释放；目录遍历最多 128 层。插件文件能力继续使用独立的授权、代次句柄和撤权校验。

NCM 与其他音频共用扩展名筛选、目录监听、原路径曲库标识和大小／修改时间失效规则。索引直接用流式解密 Reader 交给 Lofty，不生成旁置音频；标题、歌手、专辑、歌词关联 ID 与内嵌封面可由 NCM 容器补充，已有显式歌词绑定优先。封面复用本地封面目录，不设图片字节数、宽高或资产总容量上限；NCM 封面帧按容器中的图像长度、帧长度及文件实际范围校验，不额外限制帧字节数。歌曲和歌词查询仍走 `nativeCall`。

播放 NCM 在阻塞线程解码到系统临时文件，单文件 256MiB，最多 4 个存活文件（合计最多 1GiB）与 2 个解码任务；当前音频和预加载音频持有文件生命周期，停止、切换与正常退出释放。弱引用按原路径、大小和修改时间复用仍在使用的文件；源文件改变不复用旧结果。不持久化播放缓存，异常退出可能遗留临时文件，由系统临时目录清理。不会在原目录生成 MP3／FLAC。

独立转换文件属于用户保存的音乐，保留原 NCM，不纳入资源缓存清理；已管理目录的原监听照常收录转换结果并使本地查询失效。文件转换和权限查询不加入 WebUI 查询缓存，每次重新检查插件代次、权限与授权根。转换最多 2 个并行任务，按 32KiB 块验证句柄；同目录临时文件完整写入标签后原子发布，同名失败不覆盖，失败清理本任务创建的临时文件。

目录变更发出 `local-library-updated`：管理弹窗更新数量和状态，音乐工作区在扫描完成后使本地查询和歌词缓存失效并重载列表。显示本地封面的设置影响列表、播放栏和歌词封面背景，统一通过 `useCoverSource` 生效。

全量扫描期间仍需遍历路径及检查文件属性；跳过标签解析、通知合并、有界队列与图片懒加载是设计上的成本控制。实际冷启动、内存和大型曲库扫描耗时需在明确环境与曲库规模下测量。

### 本地浏览、歌单与元数据

单 FILE CUE 使用 `cue_lib` 解析，支持 UTF-8、带 BOM 的 UTF-16 与 GB18030，单文件读取上限 2MiB。扫描先处理 CUE，再扫描普通音频；以 CUE 规范化路径和轨号生成稳定曲目标识，`source.path` 仍指向原始音频，`source.cue` 保存 CUE 路径、轨号和绝对起止毫秒。按 INDEX 01 至下一轨 INDEX 01 划分，末轨止于音频末尾，保留录制间隙；不合成 PREGAP/POSTGAP 静音。CUE 标题、艺术家和专辑覆盖整轨标签，技术属性与内嵌封面复用原文件，分轨歌词绑定独立保存。缺少内嵌封面时复用“本地专辑与封面”中的候选规则，按 CUE 目录搜索外部图片，资产按内容摘要命名并供分轨共享；不设单图字节数、宽高或资产总容量上限，解码器保留 64MiB 分配预算。图片替换、移除后下次扫描更新分轨封面，不改变原整轨标签缓存；损坏或不可读候选继续尝试下一张。

本地歌曲、搜索、专辑／艺术家详情和本地歌单均将 CUE 分轨作为普通歌曲行显示；每条分轨保留独立的播放、移除和追加操作，专辑列显示分轨所属专辑并可打开本地专辑详情。列表搜索和排序直接作用于各分轨，播放仍按当前显示列表逐曲入队；本地歌单写入沿用既有失效规则，中途失败保留已成功添加的曲目并显示错误，重试由既有歌单去重处理。

原整轨索引与来源关系保留，由 `visible_local_tracks` 根据已入库的 CUE 曲目隐藏；本地列表、搜索、实体、歌单与目录数量共用该视图。目录同步移除 CUE 分轨后，仍在曲库的原整轨重新可见，原文件和歌单关联不删除。CUE 文件每次扫描有界重读，原音频继续按大小／修改时间跳过标签解析；不新增资源缓存。多 FILE、损坏 CUE、缺失音频或越界时间报告错误，不生成新的分轨条目；完整目录扫描沿用来源对账移除旧分轨。单独打开 CUE 使用独立来源，重新打开同一 CUE 对账旧轨号。

播放使用浏览器媒体位置定位起点并检查分轨终点，进度、恢复和系统媒体时间线均相对当前分轨；本地整轨歌词沿用 AMLL 解析后截取并偏移到分轨时间线，在线歌词按各轨元数据独立匹配。CUE 不走普通 URI 预加载交接，在浏览器反馈到达分轨终点后复用队列切歌、循环和随机策略；当前不保证 CUE 轨间无缝衔接。此功能不切割导出音频文件。

`local_entities` / `local_entity_detail` / `local_entity_tracks` / `local_track_information` 通过 `nativeCall` 复用统一查询缓存。实体列表每页 30 个，歌曲每页 100 首；额外读取一条判断续载，歌曲列表虚拟渲染，整组播放最多 1000 首。艺术家与专辑关联在 SQLite 索引中维护，设置分隔符时在事务中重建，不逐页加载完整曲库到 WebUI。

本地搜索页分别持有音乐、艺术家和专辑的分页状态，“所有”和单分类视图共用结果，切换分类不重发首批查询。三类均成功完成且无结果时隐藏搜索分类导航并显示统一提示；加载中与失败不视为空结果。关键词或曲库刷新代次变化时重新创建搜索视图，旧请求沿用分页查询的代次隔离。

`local_entities` 保存首次遇到艺术家时的封面，重扫、重启和标签更新不改头像。专辑键由专辑名与专辑艺术家组成，缺少专辑艺术家时使用原始艺术家标签；详情按碟号、音轨和标题排序。新导入时维护索引，修改艺术家分隔符时事务重建；启动不再根据旧索引版本回填历史曲目。`local_metadata` 保存 Lofty 读取的音轨及音频属性，详情弹窗按需在阻塞线程重读文件，失败可重试。

本地歌单及歌曲顺序保存在独立 SQLite 表中，与在线账号、歌词资源缓存无关；最多 200 个歌单，每个 10000 首，加入时去重，只接受本地歌曲。删除歌单只删除其关联，移除目录后不显示已退出曲库的曲目，重新收录同一路径可恢复对应歌单关联。成功写入通过 `nativeCall` 和 `local-library-updated` 清理本地读取缓存并刷新页面，失败保留缓存。

`localPreferences` 保存最多 16 个普通文本分隔符（每个最多 32 字节），空列表视为单一艺术家。更改时推进歌词服务缓存代次并清空运行时结果，保留 TTML 文件；前端重新取词，旧响应不得更新新偏好下的页面。在线解析失败可跳过已失败来源并继续下一在线来源，在线歌词异步刷新只更新当前已采用的同一来源。

## 插件下载文件

网易云下载插件的任务记录使用自身 storage 分区（最多 32 项）；配置复用修订快照，账号凭据使用系统凭据库并在卸载时清理。任务记录不持久化 Cookie 或临时资源 URL。传输与进度不加入查询缓存，每次验证插件代次和权限。下载使用外部读写授权根，与播放缓存独立；缓存清理、插件卸载和目录授权撤销不删除已完成的外部音频文件。已有本地音乐目录继续使用原变化同步与缓存失效规则。

## 基础音乐适配器接线（ADR 0006 阶段二）

当前来源与补充来源顺序作为设备偏好保存在 SQLite 设置 `musicSourcePreferencesV1`，与账号、播放队列和资源缓存独立。`music_source_preferences` 每次读取实时状态，不进入 `nativeCall` 查询缓存；写入核对修订号，先写盘再发布新值及 `music-source-preferences-changed`。切换角色不推进来源会话或适配器实例代次，不撤销已交付音频。停用或缺失的已保存来源保留，显式新选当前来源必须已注册且启用。账号登录／选择成功后通过 `music_source_intent`／`music_use_source` 检查独立用户操作代次，再切换工作区；较新的明确操作阻止旧登录抢回来源，启动恢复与自动刷新不切换。来源操作与登录挑战实时处理、不加入查询缓存；`music_cancel_login` 撤销挑战，后端凭据写入同样核对取消状态。

聚合搜索复用 `music_query` 的作用域缓存与后端请求预算，每来源独立游标且最多一个在途分页。来源偏好、账号、实例与写入事件重新建立查询实例并拒绝旧交付；过滤来源复用同一实例内结果，不改变偏好。每来源每类型最多保存 1000 项，达到上限停止续载并提示；错误保留先前结果和游标，只由明确重试继续。临时播放 URL 不进入搜索结果。收藏整体播放按来源读取最多 10 页、1000 首，执行队列操作前复核初始作用域，拒绝混入账号／实例变更后的批次。

`music_queue_track` 按统一作用域读取单曲并保存到既有曲目表；`music_queue_tracks` 将已经读取的同来源统一元数据转为队列项，每批最多 100 首、2MiB，核对作用域后事务保存，两个操作均不进入查询缓存。通用在线项保存 `source.kind=online` 及完整 `MusicTrack`，key 使用引用的 JSON 元组编码，曲目表来源列使用真实平台；不保存临时播放 URL 或凭据。所有在线项使用标准引用元组 key；本地项保留宿主路径，历史网易云项和旧 key 不再兼容。详情读取继续经 `music_query` 和现有作用域缓存，按来源／实体／游标隔离。实际跨来源解析通过统一播放服务与资源租约，不使用工作区当前来源改写曲目。

单曲查询沿用上述 Rust 有界缓存，不新增通用缓存或持久化元数据表。当前账号与实例作用域进入缓存条目的检查，清理资源缓存仍使原在途请求不能回填。在线播放地址不进入 `nativeCall`、单曲查询缓存或持久队列；统一管理器只登记最多 16 个后端资源所有权，并在账号／来源变化或过期时拒绝尚未交付资源。已交付播放核心的独立 HTTP 资源继续按音频管线读取。

本地 NCM 准备位于 `local/playback_resource.rs`，保持原文件统计复用、双解码任务及临时文件生命周期规则。播放解析预算、响应上限和阶段三迁移注意事项见 [音乐适配器记录](music-adapters.md#阶段二修改记录与注意事项2026-10-10)。

## 统一音乐业务与账号缓存（ADR 0006 阶段三）

### 在线歌单快照

宿主 `music/collections/` 统一处理在线歌单浏览与队列准备，宿主及功能插件的歌单 `music_query` 共用该入口。歌曲正文仍仅存在既有 `tracks`；同一 SQLite 数据库增量建立 `music_collection_snapshots` 和 `music_collection_tracks`，保存按来源、账号、歌单隔离的快照头及有序曲目 key。歌曲和分页进度在同一事务内提交，空页及重复曲目也推进平台分页；快照从未完成到完成的过程不以已显示条数猜测上游 offset。只初始化当前表结构，不补齐历史歌单表字段或回填旧数据。

新鲜期 10 分钟，过期或跨重启可立即使用旧快照并后台核对；网络失败保留旧快照，后台重试间隔至少 30 秒。关系缓存全局最多 128 份快照、32MiB 序列化关系与快照头数据，按最近访问淘汰；这是关系数据预算，不等于 SQLite 文件大小或内存占用。候选刷新不能淘汰自己正在替换的有效快照；容量不足时保留旧内容并拒绝此次更新。淘汰关系或删除账号不删除共享 `tracks` 元数据，本地曲库及本地歌单保持原有生命周期。现有歌词磁盘缓存的开关、目录及清理仍只控制歌词，歌单快照按自己的容量、刷新与账号规则维护。

前端使用宿主快照游标，绑定当前运行、账号／实例／写代次、歌单及刷新代次；平台游标只在原运行作用域中继续使用，跨重启或失效后从新分页上下文核对。后台刷新写入独立候选快照，达到原已加载范围或集合结束后原子发布，通过 `music-collection-updated` 只失效对应查询和首屏展示缓存，不推进业务写代次，不清空正在显示的列表。已有页面继续使用自己的快照；需要续载时若新旧前缀不一致，保留已显示内容并提示重试重新读取，不拼接两个版本。

完整的前 1000 首或已完成的小歌单直接关联查询 `tracks` 组装队列，不调用适配器读取详情；仅有部分前缀时先将此前缀入队，再按原平台游标补齐缺失页，浏览和播放共用同一歌单的缺失请求。跨重启的旧快照先用于入队，后台核对与队列分离；补齐只有在已入队前缀仍一致时才能扩展，保持当前歌曲、进度和播放 revision，前缀变化则保留当前队列并提示歌单已更新。暂停、停止、清空、切歌和队列编辑取消旧准备；保留 12 秒队列准备期限及 1000 首上限，不缓存播放地址。

快照命中及事务提交前后仍核对来源可用性、能力和完整作用域；写操作成功后失效该来源的歌单关系，失败写操作保留它们。手动 `refresh` 强制联网并撤销旧刷新写回；删除账号清理对应关系。数据库工作进入阻塞任务，完整队列批量读取；已由共享查询保存的页面通过只读 `music_stored_tracks` 取得既有队列 DTO，避免再次使用 `music_queue_tracks` 写入相同歌曲。专辑、歌手、本地歌单和其他查询沿用原路径。

### 其他统一查询

歌单查询命中曲目元数据校验失败时，首页最多重新获取一次该歌单，不转换不合法的缓存记录；重新获取失败时报告实际错误。续载遇到同类问题时停用对应快照、推进刷新代次并返回 `StaleContext`，重试从首页获取新快照，不混接旧前缀。共享曲目记录和其他歌单快照不随之删除；诊断仅记录静态校验规则与行号。

网易云歌单分页、详情、编辑前归属检查及私人雷达读取详情时使用 `n=0,s=0`，只请求完整歌曲 ID 列表和歌单元数据，不附带未使用的歌曲正文和订阅者预览；歌曲信息仍按当前分页单独读取。分页间仍会重新读取详情，不新增后端详情缓存；继续通过 `nativeCall`／`ScopedMusicQueries` 复用既有查询缓存及账号、实例、写操作和手动刷新失效规则。

WebUI 在线读取统一经 `ScopedMusicQueries`：`musicClient` 使用统一入口，先读取 `music_context` 再以完整作用域构造缓存键，返回与缓存命中交付前再次验证。作用域由宿主序列化的 `[SessionContext, 适配器实例代次, 写代次]` 组成；只允许同会话、同实例下的普通读取恢复，未知作用域格式不推测身份。缓存清理、单键刷新和容量淘汰由 `RuntimeCache` 统一转换为 `CacheInvalidatedError`；失效覆盖等待结果与异步交付验证期间，旧请求不能交付或回填。缓存项刷新不等于账号重置：后者使用 `context` 失效原因推进上下文代次，即使作用域字符串相同也拒绝旧调用。

同身份写入或缓存刷新后，普通在线读取最多尝试三次，每次重新核对作用域并合并同键请求；真实请求错误不自动重试。账号切换、来源停用／重载拒绝旧读取；带旧游标或非零 offset 的续载不得跨写代次重放，由页面重建分页；入队操作不重放。独立歌词、本地信息与封面维持原失效策略、容量和 TTL，不绑定在线身份，也不加入上述自动恢复。

`music_query` 与 `music_read_track` 复用 nativeCall 的现有有界查询缓存；参数含稳定来源、实体引用／完整业务请求和 `music_context` 返回的会话／实例／写代次作用域。宿主 musicClient 在缓存命中前后复核作用域，停用来源后已缓存元数据不能作为成功结果返回。本地信息、一言、字体和独立歌词不绑定网易云作用域。

成功统一写入推进来源写代次，拒绝写前在途查询的旧响应，并发出 `music-changed`；账号变更发出 `music-account-changed`。前端统一监听并清理查询缓存，账号 Provider 重置异步读取并校准按来源共享的收藏展示；选择／删除账号、登录／退出沿用失效入口。统一客户端写入保守清空现有查询缓存，失败不清理成功缓存。歌曲元数据继续复用 Rust 原 128 条缓存，键为 EntityRef、命中和回填复核账号、实例、写入和清理代次；不缓存临时播放地址或凭据。

系统凭据与 `musicAccountsV2` 是账号持久数据，不是资源缓存，清理资源缓存不删除它们。账号删除墓碑及失败重试保持有效；旧 `musicAccountsV1` 和 password 凭据不再读取或迁移，需重新登录。公开封面继续保留，歌词保持既有专用失效与来源回退，不增加第二套歌词缓存。

## 启动展示预览

`account_profile_snapshot` 实时读取宿主当前选中的保存账号，仅返回展示信息，不做网络验证、不返回凭据。界面先恢复展示，再调用既有 `account_profile` 验证；账号变更推进请求代次，旧响应不得发布。来源状态通过共享 store 统一读取与订阅，合并并发刷新，不作为权限判断缓存。

音乐库保留上次成功读取的首页摘要（最多 12 首喜欢歌曲）和首批全部歌单（最多 30 项），使用 `nons-library-preview-v1` 本地展示预览。每账号按 JSON UTF-16 长度估算最多 128 KiB，最多两个账号，有效期 24 小时；不保存图片字节、凭据、播放地址或本地目录。只有宿主确认当前账号后才读取对应预览，账号切换隔离展示；页面仍通过 `nativeCall` 及统一查询缓存获取当前内容。成功空列表替换旧展示，刷新失败保留已有展示并显示错误；音乐变更和音乐库写操作清除预览。存储不可用、超限或内容无效时退回骨架，不阻塞启动。

封面与插件前端任务在首次绘制后启动，隐藏窗口以 200ms 调度兜底，组件卸载取消尚未开始的任务；后续交互立即执行。播放核心初始化与音频播放不延迟。全屏播放器采用按需加载，隐藏页面不启动歌词渲染；打开在线收藏详情不触发无关音乐库首页请求。

## 本地专辑与封面

本地专辑以原始专辑标题作为全局身份，不 trim、不折叠大小写，也不按目录或专辑艺术家隔离。专辑艺术家仅参与展示；存在非空专辑艺术家时收集去重后的集合，全部缺失才回退歌曲艺术家，统一使用现有分隔符拆分。多碟共享专辑实体，详情按碟号、音轨号、标题、歌曲 key 排序。索引版本变化仅重建艺术家与专辑关系，保留曲目、播放历史与本地歌单。

封面按碟号、音轨号、规范化路径、歌曲 key 稳定排序，先选内嵌图片，再按目录顺序选外部图片。同目录 Folder/folder、Cover/cover 优先于其他图片，然后搜索一层 art、scans、scan、booklet、images、image、cover、covers、coverart、albumart、gallery、jacket、artwork、bonus、bk、cover artwork、cover art 子目录；同组按规范化相对路径排序。外部扩展名支持 jpg/jpeg/png/bmp/gif/jxl，大小写不敏感。CUE 分轨使用 CUE 目录的外部图片，保留独立曲目标识。

候选经过完整解码校验，解码器保留 64MiB 分配预算；JPEG XL 转为 PNG。实际资产按内容 SHA-256 去重并原子写入 covers，不设单图字节数、转换后 PNG 字节数、宽高或资产总容量上限。损坏或不可解码时继续后续候选，全部失败使用占位。封面选择不保存候选下标，不提供手动覆盖 UI。

本地图片加载失败经实时 `nativeCall('local_cover_repair')` 恢复，仅接受当前 covers 目录内的资产路径，串行复核并恢复关联曲目与专辑。单个组件每个候选只恢复一次，二次失败停止；隐藏、切图、卸载后丢弃迟到结果。实际变更发出 `local-library-updated`，失效本地查询与展示缓存；命令不进入查询缓存，不新增前端封面缓存。

设置 → 本地与缓存 → 本地歌曲提供“重建本地封面”。任务在后台串行检查全部已导入本地曲目，绕过普通扫描的文件与目录签名复用判断，重新提取内嵌与外部封面；有效的内容寻址资产直接复用，不预先清空目录。任务只更新曲目封面与封面状态，再刷新专辑封面，保留歌词绑定、曲目元数据、CUE 分轨、本地歌单与播放历史；原文件不可读的条目保留原记录，汇总失败数并记录日志。设置显示检查进度与结果，关闭后重新打开可继续查看当前任务；同时只允许一个重建任务。完成或发生错误时通过 `local-library-updated` 失效本地查询与展示缓存，重建命令与任务状态不进入查询缓存。
