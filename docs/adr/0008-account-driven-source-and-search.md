# 账号操作驱动当前来源，聚合搜索明确曲目来源与播放音源

状态：已接受。日期：2026-10-12。本文确定目标与职责，具体交互见 [设计稿](../design/search-and-source-switching.md)；两个完整适配器与音源接入尚未完成，不将设计和库的离线检查计为上线能力。

实施进度：宿主账号成功后切换、来源驱动工作区、引用驱动收藏播放与聚合搜索调度已接入；当前仍仅随包提供网易云，QQ 完整业务及真实双平台验收待完成。单音源服务按既有指示暂缓，具体边界与验收记录见设计稿。

## 决定

在 [ADR 0007](0007-current-and-supplementary-sources.md) 的平行来源模型上，目标为完整网易云、完整 QQ 音乐适配器，以及一个提供播放资源的音源适配器。本地聚合歌单暂不实施。第三个服务尚未选定，首阶段只接明确服务协议，任意落雪 JS 导入另行设计。

账号管理器继续按来源管理账号与不透明凭据；宿主单独管理工作区当前来源。用户明确登录某平台或选择该平台保存账号成功后，切换到对应来源；查看账号卡片、自动刷新凭据与启动恢复不触发切换。其他平台账号可同时保持选中，供补充搜索与播放使用，切换不等于停用其他适配器。

来源切换以账号操作成功和来源有效、持久化成功为前提；失败保持原工作区。用户意图及登录挑战代次防止旧登录结果抢回来源。退出账号后当前来源可保留为游客，停用则明确显示不可用及切换入口；队列与已交付音频不因工作区来源变化而清空或停止。

聚合搜索由宿主协调当前来源和已配置补充来源。沿用现有搜索框、页面 shell、类型 tabs、虚拟歌曲列表及卡片，增加来源筛选与逐项来源文字；筛选 QQ 结果不切换工作区。每来源独立分页与错误状态，先到结果可展示，后到批次追加，局部失败不抹掉成功结果；同名跨来源歌曲不直接合并，已知播放限制不等于歌曲不存在。

界面区分当前来源、曲目来源和资源提供器。音源适配器只解析已知曲目的资源，不成为虚构音乐平台，不获得账号选择角色、不出现在无搜索能力的搜索来源中，也不以另一平台 ID 改写歌曲身份。音源设置按平台表达选择，实际提供器与音质在播放信息中说明，临时地址和凭据留在后端。

## 实现与取舍

QQ 优先采用独立原生源码包和成熟 Rust 客户端，保留已验证的网易云实现与统一播放核心。候选 [Rust 库](../research/netease-qq-music-api.md) 能提供搜索、详情、播放和登录基础，不能直接覆盖完整账号与写入业务；[Go 库](../research/go-music-api.md) 可补部分个人资产读取依据，也不补齐全部缺口。因此暂不为了几个读接口引入 Go 服务进程或跨语言 FFI，具体协议与许可按后续验证确定。

接受额外的当前来源配置、聚合查询状态和资源提供器契约，以换取平台身份、账号与播放策略的独立演进。实现前补实际队列／持久化／导航模型、QQ 缺失业务、响应与会话预算及平台验收；不将仅解析地址的脚本当作符合现有完整音乐适配器契约的实现。自动跨平台替代播放继续按 ADR 0007 独立设计。
