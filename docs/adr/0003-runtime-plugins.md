# 插件采用 Component Model 后端与受信任 React 前端

状态：已接受。

插件需要复用播放器能力，同时限制后端执行对播放可靠性的影响。因此后端采用 Wasmtime Component Model 与版本化 WIT，前端采用 React 模块：页面和覆盖层共享主 WebView，Windows 独立窗口通过声明的组件入口在单独 WebView 加载。独立播放核心继续有效；原先暂不启动多来源框架的阶段性约定由 [ADR 0006](0006-music-provider-adapters.md) 替代。

后端不开放通用 WASI；调用通过绑定插件身份、权限及加载代次的 Host Capability。执行时间、线性内存、并发与有效载荷分别设限，插件执行不进入音频线程。执行故障撤销实例贡献，普通业务错误保留实例。

2026-10-14 补充：外部音乐适配器的多语言 Component 交付、通用 Host 和必要标准接口子集遵循 [ADR 0009](0009-language-neutral-wasm-host.md)。语言运行时与依赖由构建方案和包承担，宿主共用接口与权限机制；这不表示当前外部适配器已经具备网络、账号或完整 WASI 能力，也不改变功能插件前端的信任边界。

前端通过受控资源协议动态加载，共用宿主 React 与公开 SDK；页面和覆盖层由插件声明注册，页面沿用应用导航。宿主只提供通用扩展入口，业务组件由插件实现，职责见 [ADR 0005](0005-plugin-capability-boundary.md)。

前端必须受信任：SDK 权限不构成恶意 JavaScript 沙箱，已执行代码和 ESM 缓存不能强制回收。独立窗口只加载所属插件声明的本地组件，不执行 activate，也不创建额外音频引擎；窗口权限及生命周期由宿主管理，单独 WebView 不表示不可信 JavaScript 隔离。若需要运行不可信前端，须另行设计隔离环境与通信协议。

具体接口、依赖版本、资源限额与构建方式见 [插件开发与使用](../plugins.md)，验证结果见 [实现记录](../implementation.md)。
