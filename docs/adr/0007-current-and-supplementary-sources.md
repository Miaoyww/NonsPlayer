# 音乐来源平行接入，以当前来源与补充来源表达使用角色

状态：已接受。日期：2026-10-12。本文确定命名与职责方向，不表示补充搜索、跨来源替代播放或部分能力适配器契约已经实现。

本决策补充 [ADR 0006](0006-music-provider-adapters.md) 的多来源使用方式；来源身份、独立适配器管理、账号隔离、播放核心、缓存与生命周期约定继续有效。

账号驱动的来源切换、显式来源聚合搜索和首阶段音源目标由 [ADR 0008](0008-account-driven-source-and-search.md) 补充，具体交互与验收见 [设计稿](../design/search-and-source-switching.md)。

## 背景与决定

用户希望主要使用一个平台的歌单、曲库和账号体验，同时从其他平台查找和播放当前平台缺少的歌曲。例如，以网易云作为当前来源，以 QQ 音乐作为补充来源；同一个 QQ 音乐适配器也可以承担完整 QQ 音乐体验。

各音乐平台及其适配器保持平行、独立的关系。采用“当前来源”和“补充来源”描述用户配置中的使用角色，弃用“主适配器”和“辅助适配器”命名，避免把使用偏好表达为固定的主从类型或适配器之间的包含关系。当前来源不等于正在播放曲目的来源，切换当前来源不改变已有队列中曲目的身份。

能力范围与使用角色分开：完整音乐适配器承载平台整体接入，按平台实际支持的能力提供歌曲、歌单、艺术家、专辑、账号和曲库等功能；部分能力适配器仅提供明确的搜索、曲目读取或资源解析等能力。完整适配器已有的能力可以直接参与补充业务，无需另外实现一份辅助适配器。完整不意味着所有平台都具备所有可选能力。

补充角色不降低业务所需能力：独立补充搜索与播放需要搜索、稳定曲目读取和播放资源解析；仅解析 URL 的实现可以配合已有曲目数据提供资源解析，但不能单独发现缺失歌曲。落雪脚本按实际能力接入，不因音源声明了某个平台就推断其提供该平台搜索、账号或曲库。

## 宿主协调与曲目归属

当前来源、补充来源及搜索／播放优先级由宿主配置和协调。各适配器只实现自身平台协议，不直接调用其他适配器；继续由独立适配器管理器管理，不按当前或补充角色拆分管理器。宿主根据实际能力及操作可用性调度请求，避免形成循环回退或适配器依赖链。

搜索聚合保留结果的真实来源与稳定曲目引用。跨来源同名曲目不能仅凭名称合并为同一曲目；展示可以组织候选版本，实际播放与持久化仍保留来源身份和跨平台关联。来自 QQ 音乐的补充曲目由 QQ 音乐适配器解析资源并进入混合队列，使用其自身账号上下文，不借用网易云身份或凭据。

歌单、收藏和曲库写操作按目标平台的实际能力执行。补充曲目可参与宿主支持的本地混合歌单；加入当前平台的远端歌单须满足该平台的身份和写入约束，不能直接把其他来源的曲目 ID 当作当前平台 ID。

## 补充搜索与替代播放

两种行为分别设计：

- **补充搜索**：按用户查询从补充来源发现歌曲，补充当前来源的搜索结果，用户选择的曲目保留自身来源。
- **替代播放**：当前来源已有某个曲目但不可播放时，从其他来源查找对应版本。原始曲目与候选分别保留身份，通过关联表达对应关系。

优先实现补充搜索。替代播放需要独立明确版本匹配与采纳策略，区分录音室、现场、翻唱和不同发行版本，不凭同名自动替换；本决策不确定自动替代、评分阈值或用户确认方式。

宿主应允许当前来源的结果先交付，补充来源的超时或失败不能丢弃已有结果。请求与结果继续遵守取消、期限、并发及容量预算；切换来源配置或查询后丢弃旧结果。账号切换与适配器停用分别按相应来源的代次使请求、缓存和预加载失效，故障不删除其他来源的队列项或账号。

## 实施边界与后续决策

现有统一音乐契约可以承载来源、能力与曲目引用，但实际队列和持久化仍保留网易云／本地兼容模型。跨来源播放接入时需同步迁移队列、曲库引用、菜单 DTO 与历史数据，不能仅修改搜索页面。

ADR 0006 当前基础契约要求单曲读取与播放资源解析。允许仅提供部分能力的实现，需要明确扩展或组合契约及注册、权限、配置与生命周期规则；本决策不把仅解析 URL 的脚本宣称为已符合现有音乐适配器契约，也不直接开放 JS 运行时或第三方包安装。

后续实现须确定补充来源配置的作用域、查询触发方式、排序与分页、搜索／播放优先级，以及替代播放的匹配和回退策略。这些策略以可验证的实际能力为依据，不承诺所有来源有相同业务或播放权限。落雪脚本的接入边界见 [接入研判](../research/lx-music-source.md)。
