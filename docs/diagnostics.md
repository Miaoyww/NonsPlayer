# 诊断日志

开发和发布版本均输出本机日志。前端捕获后的 IPC 失败、未捕获异常与 Promise 拒绝会进入控制台和原生日志；Rust 音乐服务记录来源、操作、请求编号、耗时与结果码。取消与上下文失效记为 Info，真实失败记为 Error。网易云业务转换和 WASM 执行／诊断出口保留脱敏后的失败原因。

队列曲目写入失败的 IPC 错误包含 `code`、`message` 和 `stage`，`message` 保留脱敏后的原始存储错误。原生日志同时通过日志插件事件显示在浏览器控制台，不依赖页面是否显示错误。适配器公共错误契约保持稳定。

## 文件位置与容量

- Windows 便携版：程序目录的 `data/logs/`。
- 安装版及其他平台：Tauri `app_log_dir()`；启动日志输出实际文件路径。
- 每次启动新建 `2026-10-17_14-18-55-进程号.log`，同秒同进程号冲突时追加序号。文件名和日志时间戳使用本机时区，时间戳保留毫秒与 UTC 偏移；系统无法获取本机时区时回退 UTC，并显示实际偏移。
- 单文件 2 MiB，每次运行保留最近 4 份轮转文件；启动时清理最后修改时间超过 7 天的本应用日志（包括旧版 `nons.log` 及轮转），保留其他文件。日志不进入资源缓存，清除音乐缓存不删除日志。
- 文件日志无法初始化时保留终端和 WebView 输出，不阻止启动。前端上报失败会在控制台说明，不递归上报日志错误。

不记录完整请求／响应、账号凭据和鉴权地址。Rust 恢复和错误转换统一记录操作、代码位置与原始错误的 Display 描述；网络传输同时保留最多 4 层原因链，避免 Debug 展开凭据或响应负载。日志格式化在 4096 字节处停止，再脱敏并限制最终长度。

每条诊断合并为单行；URL、JSON／数组正文及常见凭据字段后的内容被过滤。前端上报最多 16 个在途任务、48 条排队任务，每秒最多发起 48 条；超过队列容量时保留控制台记录，恢复写入后用 `diagnosticOverflow` 汇总未写入文件的条数。原生入口每秒最多接收 64 条，WASM 诊断沿用已有每秒 16 条限制。音乐服务成功日志也受文件轮转容量限制。缓存失效、写入版本变化、空歌词等正常回退与重试记为 Info。

排查时同时查看前端的 `command / source / operation / code / message / stage` 和相同时间的 `nons::music`、`nons::storage`、`nons_adapter_netease`、`nons::adapter` 日志。前端热更新不会更新 Rust 命令或文件日志配置，修改原生代码后需要重新启动开发应用。

随包功能插件的前端使用相同的诊断队列；Backend 通过受实例代次和每秒 16 条预算约束的 `diagnostic.report` 记录恢复原因。插件短链跳过、下载解析和记录恢复失败会保留原因；后台任务的 JoinError、内置适配器的错误转译和 WASM 关闭失败也有对应操作日志。
